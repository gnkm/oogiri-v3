# プロンプト設計（MVP）

本文書は MVP の **プロンプト契約**（各エージェントへ渡すもの・返させるもの・やってはいけないこと・温度の扱い・`prompts/` のファイル名）を定める。
**what**（shall）の正本は [`docs/source-of-truth/srs-mvp.md`](source-of-truth/srs-mvp.md) である。
**how**（モジュール境界・データの流れ）は [`ARCHITECTURE.md`](../ARCHITECTURE.md) である。
衝突する場合は SRS を優先する。SRS の件数 shall と禁止事項を緩めない。

実装 Issue でプロンプト本文を足すときは、本文書のファイル名とスキーマを使い、役割ごとにファイルを割らない。
プロンプト本文は `src/` に埋め込まない（SRS-MVP-IF-007、SRS-MVP-FN-005）。

## 対象外

**画像出力はプロンプト契約に含めない。** 画像用のファイル、画像モデルへの指示、テキストと画像の選択は置かない。
MVP の 5 役割はいずれもテキストの分析・生成・審査・推敲のみとする（SRS-MVP-FN-028、SRS-MVP-IF-003）。

## ファイル名

プロンプト本文は次の 5 ファイルに固定する。別名・分割・役割横断の追加ファイルは作らない。

| 役割 | パス | 内容 |
| --- | --- | --- |
| 座付き作家 | `prompts/seated_writer.md` | 分析の手順、件数、出力スキーマ |
| 回答者コーディネーター | `prompts/coordinator.md` | 軸の決め方、n 体の編成、出力スキーマ |
| 回答者 | `prompts/respondent.md` | 回答者の共通枠。実行時の芸風はコーディネーターが埋める |
| ツッコミ役 | `prompts/tsukkomi.md` | ツッコミ・除外・採点・5 案選抜。本文書き換え禁止 |
| 推敲役 | `prompts/polisher.md` | 削る・オチを文末へ・語尾。内容追加禁止。1 案 |

実行時にコーディネーターが組み立てた回答者プロンプトは、メモリ上の `RespondentSpec.system_prompt` に置く。`src/` にも `prompts/` にも書き戻さない（`ARCHITECTURE.md`）。

プレースホルダ（実行時に埋める）は次に限る。プロンプトファイル側の名前を変えない。

| ファイル | プレースホルダ |
| --- | --- |
| `prompts/seated_writer.md` | `{{theme}}` |
| `prompts/coordinator.md` | `{{theme}}`、`{{respondent_num}}`、`{{analysis_memo}}` |
| `prompts/respondent.md` | `{{theme}}`、`{{analysis_memo}}`、`{{respondent_id}}`、`{{axis_name}}`、`{{axis_description}}`、`{{style_instructions}}` |
| `prompts/tsukkomi.md` | `{{theme}}`、`{{analysis_memo}}`、`{{candidate_batch}}` |
| `prompts/polisher.md` | `{{theme}}`、`{{shortlist}}` |

`{{style_instructions}}` はコーディネーターが当該回答者向けに書いた芸風指示である。共通枠（`respondent.md`）は全回答者で同一とする。
`{{respondent_id}}` は `RespondentSpec.respondent_id` である。`{{shortlist}}` はツッコミ役が返した `Shortlist` 全体ではなく、採択 5 案とそのツッコミだけを埋めた射影である（推敲役の節を見よ）。

## 温度の扱い

温度は **LLM 呼び出しパラメータ** であり、プロンプト本文ではない。

- 数値の置き場は `config.toml` の `[agents.<role>] temperature` とする。モデル ID と同様、コードとプロンプトに埋め込まない。
- プロンプトファイルに「temperature=…」を書かない。役割の温度帯（低温 / 高温）だけを契約する。
- 座付き作家・ツッコミ役・推敲役は **低温**（SRS-MVP-FN-008、017、022）。
- 回答者は **高温**（SRS-MVP-FN-014）。
- 回答者コーディネーターの低温/高温は SRS が定めない。`config.toml` で可変とする。
- コーディネーターが回答者のパラメータを決めるとき、回答者の温度は高温のままにする。低温へ下げてはならない。
- 数値の設計既定は `ARCHITECTURE.md`（座付き作家 / ツッコミ / 推敲 `0.2`、コーディネーター `0.4`、回答者 `0.9`）。既定を変えても温度帯の契約は変えない。

## 件数（緩めない）

| 項目 | 件数 | 要件 |
| --- | --- | --- |
| 前提 | **ちょうど 3** | SRS-MVP-FN-009 |
| 凡庸案 | **ちょうど 5** | SRS-MVP-FN-009 |
| 回答者 1 体あたりの案 | **7 以上** | SRS-MVP-FN-015 |
| ツッコミ役が選ぶ案 | **ちょうど 5** | SRS-MVP-FN-020 |
| 推敲役の出力 | **ちょうど 1** | SRS-MVP-FN-025、027 |

「3 つ程度」「5 案まで」などへの緩和は禁止する。コード側の Pydantic 検証（SRS-MVP-QA-003）もこの件数に一致させる。フィールド名は `ARCHITECTURE.md` のデータ契約と揃える。

## 共通禁止

全役割のプロンプトとオーケストレーションに共通する。

- 画像の生成・選択・説明画像の出力を指示しない。
- API キーその他の秘密をプロンプト・ログに書かない（SRS-MVP-QA-002）。
- 他回答者の案・プロンプト・パラメータを、ある回答者へ渡さない（SRS-MVP-FN-016）。
- 座付き作家の前提を 3 以外、凡庸案を 5 以外にしてはならない。
- 芸風の軸をコード定数・設定の固定リスト・プロンプトの列挙拘束にしてはならない（SRS-MVP-FN-013）。

## 座付き作家

要件: SRS-MVP-FN-008〜010。ファイル: `prompts/seated_writer.md`。温度帯: 低温。

後段が共有する分析メモを作る。笑いの案そのものは出さない（凡庸案は「避ける例」であり、最終候補ではない）。

### 渡すもの

| 項目 | 内容 |
| --- | --- |
| お題 | `{{theme}}`（`--theme` の文字列） |

他エージェントの出力は渡さない。

### 返させるもの

構造化オブジェクト `AnalysisMemo`。JSON のフィールドは次で固定する。

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `theme_type` | 文字列 | お題の型（例: 定義付け、列挙、もしも）。空でない。「こんな X はいやだ。どんな X？」は **定義付け** |
| `humor_direction` | 文字列 | このお題で狙う笑いの方向。空でない。特定のネタの中身（逆・誤情報）に固定しない |
| `premises` | 文字列の配列 | **ちょうど 3 件**。お題を成立させる **型の条件**。笑いの仕組み（逆・誤情報）は書かない |
| `banal_ideas` | 文字列の配列 | **ちょうど 5 件**。凡庸で避けるべき案。すぐ嘘／毎回間違える／逆を言う／命令無視／対話で説明する型を先に潰す |

例（件数のみ規範。文言は例示）:

```json
{
  "theme_type": "定義付け",
  "humor_direction": "…",
  "premises": ["…", "…", "…"],
  "banal_ideas": ["…", "…", "…", "…", "…"]
}
```

この `AnalysisMemo` は後段の回答者 **全員** に同じものを配る（SRS-MVP-FN-010）。回答者ごとに書き換えない。

### やってはいけないこと

- 前提を 3 件以外にする（2 件や 4 件を含む）。
- 凡庸案を 5 件以外にする。
- 前提にネタの中身（逆をやる／押し通す／誤情報）を書く。
- 「こんな X はいやだ。どんな X？」を定義付け以外の型にする。
- 回答案・最終回答・画像を出す。
- 後段の役割（編成・回答・ツッコミ・推敲）を代行する。
- 凡庸案を「採用候補」として推薦する。

## 回答者コーディネーター

要件: SRS-MVP-FN-011〜013。ファイル: `prompts/coordinator.md`。温度帯: 設定で可変（SRS は低温/高温を定めない）。

実行ごとにお題に応じた芸風の軸を決め、その軸で回答者 n 体のプロンプトとパラメータを決める。

### 渡すもの

| 項目 | 内容 |
| --- | --- |
| お題 | `{{theme}}` |
| 回答者数 | `{{respondent_num}}`（`--respondent-num`、省略時 3） |
| 分析メモ | `{{analysis_memo}}`（座付き作家の `AnalysisMemo`） |

回答者の案はまだ無い。渡さない。

### 返させるもの

構造化オブジェクト `Roster`。

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `axes` | `StyleAxis` の配列 | 1 件以上。**種類も件数も固定しない** |
| `respondents` | `RespondentSpec` の配列 | **ちょうど n 件**（`n == respondent_num`） |

`StyleAxis`:

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `name` | 文字列 | この実行で使う軸の名前。空でない |
| `description` | 文字列 | その軸の笑い方。空でない |

`RespondentSpec`:

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `respondent_id` | 文字列 | 実行内で一意 |
| `axis` | `StyleAxis` | `axes` のいずれか。1 回答者 1 軸 |
| `system_prompt` | 文字列 | `prompts/respondent.md` の共通枠に、この体の芸風を埋め込んだ結果 |
| `model` | 文字列 | `config.toml` の回答者モデルを基準にする。コード定数にしない |
| `temperature` | 数値 | **高温**。回答者を低温にしない |

`system_prompt` はメモリ上にのみ置く。ファイルへ書き戻さない。

### 軸をコード定数にしない

- 軸の種類と数は本ソフトウェアが固定しない（SRS-MVP-FN-013）。
- `src/` の Enum・タプル・定数リスト、`config.toml` の固定軸、プロンプト内の「次の三軸から選べ」は置かない。
- seed が列挙する三軸（地味にリアル、ずらし、ワード）は **例** であり、拘束しない。お題によっては使ってよいが、毎回それらにせよとは書かない。
- 軸は **実行ごと** に、お題と `AnalysisMemo` を見て決める。

n 体が同じ軸に固まってはならない。少なくとも笑い方の方向がずれるよう分ける。n が軸数より多い場合は、同一軸でも指示をずらして重複を避ける。

軸は前提の言い換えにしない。前提は型の条件であり、軸は笑い方のずれである。
各体の `style_instructions` には **1 句・体言止め・具体物 1 つ・対話禁止** を含める。軸の固定リストは置かない（SRS-MVP-FN-013）。

### やってはいけないこと

- 軸を事前定義の固定集合からだけ選ばせる。
- 軸の種類・数をコードや設定の定数にする。
- 軸を前提の言い換えにする。
- `style_instructions` から 1 句・体言止め・具体物 1 つ・対話禁止を落とす。
- 回答者数を n 以外にする。
- 回答者の案を自分で書く。
- 回答者の温度を低温にする。
- 画像担当・画像プロンプトを編成に含める。

## 回答者

要件: SRS-MVP-FN-014〜016。ファイル: `prompts/respondent.md`（共通枠）。温度帯: 高温。並列。n 体。

お題に対する案を出す。互いの出力は見ない。

### 渡すもの

各体が受け取るものは次に限る。

| 項目 | 内容 |
| --- | --- |
| お題 | `{{theme}}` |
| 分析メモ | `{{analysis_memo}}`（全員同一の `AnalysisMemo`） |
| 自分の ID | `{{respondent_id}}`（`RespondentSpec.respondent_id`） |
| 自分の軸 | `{{axis_name}}`、`{{axis_description}}` |
| 芸風指示 | `{{style_instructions}}`（コーディネーターがこの体向けに書いたもの） |

他回答者の `RespondentSpec`、他回答者の案、ツッコミ、推敲結果は渡さない。
`respondent_id` の正はオーケストレータが渡した `RespondentSpec.respondent_id` とする。LLM 出力の ID が欠ける・食い違う場合は、検証前にその値で上書きする。

### 返させるもの

構造化オブジェクト `CandidateBatch`。

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `respondent_id` | 文字列 | `{{respondent_id}}` と同一 |
| `candidates` | `Candidate` の配列 | **7 件以上** |

`Candidate`:

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `candidate_id` | 文字列 | 実行内で一意 |
| `respondent_id` | 文字列 | `{{respondent_id}}` と同一 |
| `text` | 文字列 | 大喜利の回答本文。**1 句の体言止め**。空でない。対話・質問・「X と言うと Y」の導入は置かない。目安は 15〜25 字の名詞句（硬制約ではない。文字数の Pydantic 上限は置かない） |

各案はテキスト 1 本・1 句とする。箇条書きのネタ帳や画像指定は返さない。同じ型の 7 連打をしない。

凡庸案（`banal_ideas`）と同じ内容・同じ形は出さない。前提（`premises`）は壊さない。自分の軸から外れない。定義付けなら「どんな X か」を名指す。

### やってはいけないこと

- 7 案未満で終える。
- 同じ型の 7 連打をする。
- 対話形式、質問、「と言うと」で始まる導入を書く。
- 他回答者の案を参照する、模倣する、と尋ねる。
- 他回答者の出力を実行時に読む（オーケストレータも渡さない）。
- 座付き作家の凡庸案をそのまま出す。
- 画像を返す、画像プロンプトを書く。
- ツッコミや推敲まで自分で行う。

## ツッコミ役

要件: SRS-MVP-FN-017〜021。ファイル: `prompts/tsukkomi.md`。温度帯: 低温。審査担当。

残っている全案に実際にツッコミを書き、書けない案はその場で落とす。採点し、同じ軸・同じ形が重ならないよう **5 案** を選ぶ。

### 渡すもの

| 項目 | 内容 |
| --- | --- |
| お題 | `{{theme}}` |
| 分析メモ | `{{analysis_memo}}` |
| 全回答者の案 | `{{candidate_batch}}`（全 `CandidateBatch` を連結した残存全案） |

各 `Candidate` の `text` は原案のまま渡す。ここで改変しない。

### 返させるもの

構造化オブジェクト `Shortlist`。

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `notes` | `TsukkomiNote` の配列 | **残存全案** に 1 件ずつ。抜けを作らない |
| `selected` | `Candidate` の配列 | **ちょうど 5 件**。いずれも `dropped` でない案 |

`TsukkomiNote`:

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `candidate_id` | 文字列 | 対象案 |
| `tsukkomi` | 文字列 | 実際に書いたツッコミ。不能ならその理由 |
| `dropped` | 真偽 | ツッコミを書けなければ `true`。その場で落とす |
| `score` | 数値 | 採点。尺度はプロンプトで明示してよいが、件数 shall は変えない |

`selected[].text` は入力の当該 `Candidate.text` と **文字単位で同一** とする。言い換え・誤字修正・短縮も書き換えである。

選べるのはツッコミを書けた案だけである。同じ軸・同じ形が重ならない 5 案にする。

対話形式・逆張りテンプレ・時事コメント・説明が長い案は **落とす**。短縮は書き換えなので禁止する。

### やってはいけないこと

- **案本文を書き換える**（SRS-MVP-FN-021）。誤字修正、読点、語尾、オチの移動、短縮を含む。
- 対話・逆張りテンプレ・時事コメント・説明が長い案を残して選ぶ。
- ツッコミを書かずに採点や選抜だけする。
- ツッコミを書けない案を残す。
- 選抜を 5 件以外にする。
- 新ネタを足す、落選理由以外の新しい回答を書く。
- 画像の可否で落とす／残す。

## 推敲役

要件: SRS-MVP-FN-022〜025。ファイル: `prompts/polisher.md`。温度帯: 低温。

選ばれた 5 案を磨き、**ちょうど 1 案** にする。

### 渡すもの

| 項目 | 内容 |
| --- | --- |
| お題 | `{{theme}}` |
| ショートリスト | `{{shortlist}}`（採択 5 案と、それらのツッコミだけ） |

`{{shortlist}}` に埋める範囲は次に限る。ツッコミ役が返した `Shortlist` 全体（残存全案の `notes`）を渡してはならない。

| 項目 | 制約 |
| --- | --- |
| `selected` | `Shortlist.selected` の **ちょうど 5 件**。本文は原案のまま |
| `notes` | `selected` の `candidate_id` に一致する `TsukkomiNote` だけ。ちょうど 5 件 |

`dropped=true` の案、落選案の本文、落選理由のツッコミは渡さない。ここで内容を足さない。

### 返させるもの

構造化オブジェクト `PolishedAnswer`。

| フィールド | 型 | 制約 |
| --- | --- | --- |
| `text` | 文字列 | **ちょうど 1 案**。空でない。大喜利の回答本文のみ |

標準出力に出すのはこの 1 案のテキストだけである（SRS-MVP-FN-002、027）。中間メモ・ツッコミ・落選案は既定では出さない。

編集してよい操作は次の **3 つのみ**（SRS-MVP-FN-023）:

1. **削る** — 余剰な前置き、説明、重複、引用符、導入を落とす。オチが残る最短を選ぶ
2. **オチを文末へ移す** — 笑いの核を文の最後に置く
3. **語尾を決める** — 体言止めを一つに決める

5 案から 1 案を選ぶ過程も、上記の編集の範囲に収める。選ばなかった 4 案の要素を混ぜて新しい内容を作ってはならない。別案の語を足さない。

### やってはいけないこと

- **内容を追加する**（SRS-MVP-FN-024）。新しい事実、新しいたとえ、新しいオチ、別案の良い部分の合成を含む。
- 別案の語を足す。
- 引用符や導入を残す。
- 削る・オチ位置・語尾以外の編集をする。
- 2 案以上を返す。0 案で終える。
- ツッコミ文や選評を回答に混ぜる。
- 画像を返す。

## 実装 Issue への拘束

プロンプト実装・エージェント実装の Issue は、本文書を入力契約とする。

- ファイル名を変えない。役割ごとに `prompts/` を増やして割らない。
- 入力・出力のフィールド名は本文書と `ARCHITECTURE.md` のデータ契約に合わせる。
- 件数と禁止（書き換え禁止、追加禁止、相互非参照、軸の非固定）をプロンプト文言でもコード検証でも緩めない。
- 回答本文は端的（1 句）とする。前提は型の条件である。文字数の Pydantic 上限と軸の固定 Enum は置かない。
- 画像出力をプロンプト契約・ファイル・プレースホルダに足さない。
- 本文書と SRS が衝突する場合は SRS に合わせ、本文書の修正 Issue を人間へ依頼する。`docs/source-of-truth/` は編集しない。
